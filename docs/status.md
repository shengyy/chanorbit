# Test status

Version 0.1.0, schemas `chanorbit.geometry/1`, `chanorbit.stages/1` and `chanorbit.levels/1`. This document records what this repository's own tests and builds cover. Gate commands are in [CONTRIBUTING.md](../CONTRIBUTING.md).

## Covered

| Area | Evidence |
|---|---|
| Regression baselines | 15 synthetic series in `tests/golden/` (5 to 1920 inputs, 1.0 MiB compressed): daily random walk, long up and down trends, narrow range with flat bars, one-price limit bars and opening gaps, same-time revisions (daily and 5m), very short series (no stroke, MACD warm-up), retention with `max_strokes = 5` plus revisions, `min_stroke_bars = 4`, 30m, 5m (1920 bars, retention at 50 strokes) and 1m session labels, and a 1m NewBar merging 103 raw bars whose price owner is displaced by the element cap |
| Stage baselines | 43 synthetic daily cases in `tests/golden/stages/` (155 to 387 inputs, plus 3 and 40): second, third and second-like stages, each with `within`, `beyond_start` and a withdrawn rebound with its times (second-like from five series); a stage at the input it first stands and one input earlier (all three kinds); `observe_from` on that input (first time unknown) and one input before it (known); first time unknown at the default-style observation start for second and third (stage standing at a 60–99 input prefix, then 160 constant or rising inputs) and for second-like (observation started on its first input, same tails); revisions inserted before every seventh observed input, the input after the retest's end and the withdrawal input, answering as the series without them; retest low exactly at the path guard (no stage) and one tick above (stage); no stage, no stroke and MACD warm-up. Compared strictly, every field |
| Stage rules | Inserting an earlier different version before every fifth input leaves the stages unchanged; `observe_from` after the last input leaves every first time and age `null`; a malformed `observe_from`, a `null` one, and one in a `geometry` request (string or `null`, also through the real binary) are `invalid_request`; `stages` errors carry the stages schema |
| Levels baselines | `tests/golden/levels/`: 12 synthetic four-level cases (daily, 30m, 5m, 1m from one synthetic 1m session path, some with whole sessions missing from the finer levels, cut at intraday moments and at the close; picked from 19,200 to cover 79 listed features), 1 synthetic single-level case whose latest centre departs in the `tail` (element cap makes the candidate unavailable), and 3 transformed single-level cases (5m cut from real series, prices `2p + 3`, times 156 weeks earlier, synthetic volumes) for a departure in the extension of the last stroke and an ended centre's retest back inside the core. Covered: latest `inside`, `departed` (member, later stroke, `unfinished`, `extension`, `after_extreme`, `tail`) and `formed_out`; ended `departed` (member and closing stroke) and `formed_out`; a departure against its exit side (latest and ended); `retest_role` `entry`, `member` and `null`; `versus_edge` `beyond` and `inside`; every last-close position; `versus_next` core `above`/`below`, outer `above`/`below`/`touch`/`overlap`; every comparison pair; the `extension` point and `passed_by` for every point; every zone; forces with exactly two and with three or more strokes; `child_starts_after` `last_start`, `last_end` and `unfinished_extreme`; `zones: null` with each reason; `missing_material` with `child: null`. Not covered: `versus_edge: at` (reachable for an ended centre, never produced by 1500 synthetic seeds or a local real-data run); core `touch`/`overlap` and a latest `at`/`inside` cannot occur ([centre list](structure-contract.md#centre-list), [centre state](structure-contract.md#centre-state)). Compared strictly, every field, also as one batch through the real binary (`--jobs 1` and `--jobs 8` identical) |
| Levels rules | Every baseline: the latest state is `inside` exactly when the last close is in the core, a latest retest is `beyond`, an ended centre is never `inside`, `formed_out` has three members, the next core is `above` or `below`, placed zone objects end after the last-stroke start (none crosses it when the child series starts inside the last stroke), `forces.last_stroke` has one row for two same-direction strokes in `inside_last` and two rows for three or more; revisions before every fifth bar of every level answer as the series without them; empty `levels`, empty, missing or repeated `name`, `observe_from` at either level, a bar error named `levels[i].…`; two-bar levels are `missing_material` with `child: null` and `child_reason`, and the finest has neither; unit tests for the child time and for the zone rules over every span on a grid, with and without the unfinished boundary, and with boundaries before the child series; the engine's state assertions held on a local real-data run of 77,380 four-level requests (not committed) |
| Per baseline | Snapshot after 5–15 input prefixes and the final response, every field; one state row per input; final NewBars of every stroke and of the unfinished window with their raw elements; retained raw times; batch equals incremental; default-parameter baselines also through the request text |
| Comparison | Strict: same keys and lengths, same JSON types (an integer never equals a float, a boolean never equals a number), floats equal bit for bit, no tolerance. All baselines pass |
| Revision and time order | Feeding every same-time revision equals feeding only the last version, including when revisions undo retention pruning and stroke withdrawal; adjacent equal times through the contract equal the last version; a decreasing time and a non-adjacent repeat are `invalid_bar` |
| Element cap | A NewBar keeps its first 100 and latest raw bars; `confirmed_at` is unchanged and the candidate reports `anchor_price_source_missing` when the owner was displaced |
| Input contract | Only `YYYY-MM-DDTHH:MM:SS` parses (space, bare date, single-digit hour, padding, fraction, zone, leap second and invalid dates rejected); every output time in the baselines has the same format; prices and volumes out of range, `high < low` and `close` outside `[low, high]` are `invalid_bar` naming field and index, for both commands (a one-price bar and a close at either end stay valid); a positional array or other non-object JSON and a request over 200,000 bars are `invalid_input` |
| CLI | Real binary: single request against a baseline, batch of the default-parameter baselines with malformed, short-column and unknown-field lines, input order, error isolation, identical bytes for `--jobs 1` and `--jobs 8` (both commands); a non-UTF-8 batch line fails alone (exit 1) and a non-UTF-8 single request is an error object; empty and whitespace-only batches exit 0 with no output; `--jobs` without `--batch` and `--jobs 0` exit 2; `--version`/`-V`, `-h`; zone-suffixed time and unknown field rejected; a closed stdout, with stderr open or closed, exits 3 with no panic for `geometry`, both batches, `--version` and `--help` |
| Panic isolation | Library unit test (test builds only: a request whose id is the probe panics inside its computation): for `geometry`, `stages` and `levels` the probe request is an `internal_error` with its id, schema and the panic message, and its neighbours answer exactly as on their own; a non-text panic payload is named. Not triggered through the shipped binary, which has no such hook |
| Builds | `aarch64-apple-darwin` release binary (links only `libSystem`); `x86_64-unknown-linux-musl` static-pie binary built in a `linux/amd64` container and run there under emulation, producing byte-identical `geometry` and `stages` batch output to the macOS binary on a local 1677-request batch and byte-identical `levels` output on a local 9,673-request four-level batch (not committed); the maturin wheel installed with `uv pip install` from the git source at a commit into a fresh virtual environment puts a `chanorbit` executable there whose `--version` (three schemas) and `geometry`/`stages`/`levels` output on those batches and a 77,380-request `levels` batch are byte-identical to the cargo-built binary |

## Not covered

- The engine's `non_finite` reasons and the non-finite candidate path. The command line rejects such input before computation, so they are reachable only through the library, and have no test there.
- `max_strokes` other than 5 and 50, `min_stroke_bars` other than 4 and 6 (library only; the command line uses 50 and 6).
- `stages` baselines are synthetic daily series only; no intraday or real-data stage case is committed.
- `levels` baselines are synthetic apart from three transformed single-level cases.
- Native execution on a Linux x86_64 host; only container emulation was run. Windows is not a target.
- Long series that form no stroke (quadratic time, see [architecture.md](architecture.md#data-flow)) have no timing test. Performance has no threshold or test; `cargo run --release --example bench` gives local readings only.
